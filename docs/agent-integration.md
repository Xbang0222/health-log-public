# 接入一个 AI 助手

普通人看[使用指南](user-guide.md)。本页给能读取文件、运行命令的 AI 或接入方。
模型不限品牌；仅有聊天能力、无法访问运行环境的模型不能直接保存账本。

## 第一次接手

1. 确定程序目录和用户的持久账本目录；明确使用绝对路径，不把程序目录当个人账本。
2. 按[安装说明](portable-install.md)准备依赖。已有账本先检查，格式 1 可继续查询；需要写入时按
   [迁移说明](migration.md)完整备份后升级，不新建空账本替代。新账本用 `init`；食品数据按安装说明
   优先从程序目录的 `data/foods/raw/cn6`、`data/foods/raw/boohee` 分别执行 `foods build`，
   没有完整本地快照时再用 `foods fetch`。已有有效食品库不因接手而重建。
3. 读取账本 `HEALTH_LOG_V2.md`（存在时），否则读账本 `AGENTS.md`。保留原指南中仍适用的个人偏好。
   源码根目录的 `AGENTS.md` 是开发约定，不能替代账本规则。
4. 调用 `doctor`、`check` 和 `recent`，知道环境、记录和未完成事项后才向用户说明状态。
5. 新用户只需学会“什么时候、什么食物、大概多少”和“改一下、查一下”。不先收集姓名、身高或目标，
   老用户直接接着处理当前请求。具体对话规范以[运行模板](../src/hl/data/templates/AGENTS.md)为准。

```sh
python3 /程序目录/health-log/scripts/hl.py --data /持久目录/health-data doctor
python3 /程序目录/health-log/scripts/hl.py --data /持久目录/health-data recent --limit 20
```

指定 `--data` 只选择账本，不会让宿主自动加载规则。换 AI、换聊天或换电脑都要重新完成读取规则与查询。
已有格式 2 账本不会因更新源码或重跑 `init` 自动覆盖其指南；需保留个人规则，再将当前模板的操作规范
合并进实际入口文件。不要为了更新说明改动账本数据或回退格式。

## 理解与保存各负其责

AI 理解语音转写、日期、餐次、品种、份量、补充、更正、否定和未来打算。
引擎检查结构、计算营养、标记估算、处理版本与重复调用、保存记录及历史。
引擎不会再次用关键词证明 AI 的理解正确，也不会判断人真实吃了多少。

“一碗面”已有份量，可以估算；“吃了面”缺份量，需要补问。疑似“20度”等转写歧义要问清含义，
不能擅自改成克或毫升。能独立确定的项目先提交，部分成功只按实际返回结果报告。
默认反馈保留用户的数量与单位，附必要估算或默认提示；用户问明细时再返回营养数字。

唯一日常写入口是 `intent`，不要直接编辑受保护数据。

```sh
python3 /程序目录/health-log/scripts/hl.py --data /持久目录/health-data intent --file - <<'JSON'
{"request_id":"会话UUID:消息1:早餐","action":"add","said":"早餐吃了两个鸡蛋","date":"2026-10-25","meal":"早餐","items":[{"name":"鸡蛋","amount":{"n":2,"unit":"个"}}]}
JSON
```

示例日期必须替换成真实语境中的日期。实际集成优先用 stdin 或文件传 JSON，避免拼接未经转义的 shell 字符串。
每个用户事件的每个动作有稳定唯一 `request_id`；同次重试复用它，不能用新 ID 绕过拒绝。
`said` 保留完整原话，后续补充放 `answers`。用 `recent` 查询目标身份和版本后更正，只改点名项目。

完整动作、估算输入、更正和确认协议维护在账本模板中，本页不另造一套协议。

| 返回状态 | AI 应怎样处理 |
| --- | --- |
| `ok` | 结合 `recorded` 判断是否实际写入；成功后再说已记、已改 |
| `duplicate` | 没有再次写入；按 `current_status/current` 说明当前状态，不能照抄历史结果 |
| `needs_input` | 事实尚缺或批量删除待确认；说清未完成部分，补齐事实或等待新的确认回复 |
| `needs_estimate` | 已知食用量，需要有依据的营养估算；由 AI 补估算，不让用户填写机器字段 |
| `rejected` | 参数先自行修正；版本冲突先重新查账，不能盲目覆盖 |
| `error` | 未完成；说明实际问题，按恢复说明处理，不能假称保存或重签损坏记录 |

单条明确更正无需反复确认。批量删除必须先展示冻结的范围，再等待用户的新回复；
不能把发起删除时说的“确定”当成看到预览后的确认。用户取消后停止，旧请求和旧确认不能复用。

## 查询与适度提醒

| 工具 | 用途与边界 |
| --- | --- |
| `recent --limit 20` | 最近条目、版本、计划、默认和未完成事项；`drafts` 只含摘要，不能据此臆造原输入 |
| `today --date YYYY-MM-DD` | 指定日期的实际记录与汇总；无条目表示未记录，不表示没有进食 |
| `find 牛奶 --from YYYY-MM-DD --to YYYY-MM-DD` | 按词、日期检索，可加 `--meal`；`--history` 包括更正与删除历史 |
| `report --days 14` | 多日记录汇总；缺记录的日期和未知营养不能当零摄入 |
| `history` | 更正前后与操作历史 |
| `food search 牛奶` | 搜索食物；不要混淆用户给的品种和查询匹配 |
| `plan show` | 已有用户目标，不能凭空替用户设置目标 |

打开/继续相关对话或用户回顾记录时，查到未完成事项可以简短提醒一次。
区分“补记未完成”“更正未生效”“尚未删除”，不能把未完成更正说成原餐不存在。
跨会话只有摘要时，先核对当前记录与用户意图再恢复。未发生变化的待补项不要每轮催问，取消后停止。
没有计划、没有体重、没有三餐齐全都不自动算漏填；用户自己的记录范围才是依据。

项目没有后台调度和推送，也没有持久的提醒去重标记。只有外部宿主确实提供且成功设置提醒，
才能声称安排了定时通知。AI 不能仅因为读到这份文档就说“晚上我会自动提醒”。

## 数据与宿主边界

本地引擎不调用模型 API；宿主决定送给模型的上下文和工具结果。用云端 AI 时，它会处理你提供的
对话及工具返回内容，不能把“本地存储”说成“所有信息绝不离开电脑”。不额外上传整份账本或密钥。
程序仓库可分发，个人账本必须保持私有，详见[项目与发布边界](publication.md)。

hooks 仅增强原话来源采集和直接写保护，普通意图调用不依赖它们。
默认来源是 Agent 提交；核验可选宿主采集消息后才能称为宿主采集，二者都不证明语义一定正确。
用户需要备份或换电脑时带走整个账本，包括 `.hl`；只复制 Git 跟踪文件不是完整备份。
