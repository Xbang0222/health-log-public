# 程序项目与私有项目

普通用户接触两套内容：可复用的 health-log 程序，以及自己独立保存的个人账本。
下载或更新程序不会把个人账本变成程序的一部分，也不会自动把记录同步到 GitHub。

| 内容 | 放哪里 | 可公开吗 |
| --- | --- | --- |
| 通用源码、规则模板、安装入口和使用文档 | 程序项目 | 按选定许可证分发 |
| 通用食物概念、量词和模式文件 | 程序的 `src/hl/data` | 作为运行资源随程序分发 |
| 饮食、体重、个人目标、默认、原话和个人标签 | 独立个人账本 | 不公开；如使用 Git，远端须为私有 |
| `.hl/secret`、收据、完整历史和食品缓存 | 私人持久账本和完整备份 | 不公开；普通 Git 历史也不是完整备份 |
| 自动化测试、夹具、模型测试对话和审查材料 | 维护者的私有开发区 | 本项目选择不公开 |
| API 密钥、宿主设置和机器特定配置 | 各自的私有环境 | 不放进程序或公开示例 |

维护者的私有开发区服务于软件开发，与个人账本是两回事，不要求普通人再建一份开发项目。
私有开发区保存的测试不会替用户记录健康数据，个人账本也不应充当测试环境。

## 个人账本

把记录放在与源码分开的持久目录，例如 `~/health-data`。可以只用本地目录和私人备份，
也可以另外建立私有 Git 仓库保存其允许跟踪的内容；不从公开模板直接上传真实记录。
每次整目录备份都带上隐藏文件，特别是 `.hl`。Git 不包含的密钥与收据仍须单独受到完整备份保护。

程序在自己的目录建立 `.venv`；账本保存记录和 `.hl`。两者名字相似但用途不同，
不能把 `.hl` 当成可重装的运行环境删除。换机步骤见[安装说明](portable-install.md)。

## 程序如何分发

运行所需的源码、模板、依赖配置和用户文档采用允许清单进入源码包。
测试与过程材料即使仍在维护者工作目录，也不应进入 wheel、源码包或公开源码快照。
旧构建包可能采用不同清单，发布时必须重新构建并检查成员，不复用旧 `dist` 文件。

`.gitignore` 只影响未跟踪文件，不能抹掉 Git 历史。带有私有开发材料的旧仓库要继续私有；
公开项目应从审阅后的干净源码快照建立独立历史，不能直接把旧仓库改为公开。
公开问题、附件、Actions 日志和发布包也不能包含这些材料。

程序采用 [MIT 许可证](../LICENSE)，与个人账本的访问权限无关；第三方食品数据各遵循其来源条款。
公开源码入口是 [health-log-public](https://github.com/Xbang0222/health-log-public)。
维护者的旧开发仓库继续私有；公开项目使用独立源码历史，不继承私有开发记录。

构建清单依据 [Hatch 文件选择配置](https://hatch.pypa.io/latest/config/build/#explicit-selection)；
项目采用的 `src` 布局见[架构说明](architecture.md)。不公开测试是本项目选择，不是行业统一规定。
