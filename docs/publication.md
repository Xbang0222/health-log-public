# 公共模板与自己的私有项目

health-log 的普通使用方式是：从公共模板取得一份完整项目，创建自己的私有副本，
在这一目录里保存程序、规则和个人记录。AI 只打开这一个目录，不要求再维护独立程序路径。
也可以不用 Git，把完整项目放在普通私人持久目录中。

公共模板是可复用的起点；加入个人记录后的完整项目应保持私有，不推回公共模板。
下载、初始化或更新程序都不会自动同步到 GitHub，也不会改变任何仓库的可见性。

| 内容 | 位于项目哪里 | 分发范围 |
| --- | --- | --- |
| 通用源码、规则模板、安装入口和文档 | `src/hl`、`scripts`、根文档与 `docs` | 按程序允许清单公开 |
| 自有食物概念、菜谱、量词与模式 | `src/hl/data` | 作为运行资源随程序公开 |
| 食品库来源、条数、版本和校验清单 | `data/foods/README.md`、`manifest.json` | 可公开，不包含完整第三方数据 |
| 完整第三方原始数据与整理快照 | 私有工程的 `data/foods/raw`、`compiled` | 私有保留，不按项目 MIT 许可公开再分发 |
| 个人记录、配置、目标、默认和食品标签 | `hl.toml`、`log`、`plan.yaml`、`defaults.yaml`、`foods` | 用户私有项目和私人备份 |
| 密钥、收据、事务、完整历史和食品缓存 | `.hl` | 私有；不能遗漏于完整备份 |
| 个人偏好和实际使用规则 | 根 `AGENTS.md` 及其他个人指南 | 私有；升级时合并，不直接覆盖 |
| 自动化测试、夹具、模型对话与审查材料 | 维护者的私有开发区 | 本项目选择不公开 |
| API 密钥、宿主设置和机器配置 | 各自的私有环境 | 不放进公共模板或示例 |

“完整私有副本”指完整的可用程序加自己的账本，不是取得维护者的私有测试、开发历史或受限数据。
维护者开发区与个人日常项目各有用途，普通用户不必再建一份开发项目。
私有项目也不能被擅自拿来做工程测试。

## 保存自己的项目

选择长期保留的私人目录。若使用 Git 远端，创建自己的私有仓库，并核对远端与可见性后再自行同步；
不要把带记录的分支推到公共模板。公共模板的 `.gitignore` 默认忽略 `hl.toml`、`log/`、计划、
默认、个人 `foods/` 和 `.hl/`；建立了私有仓库也不会自动解除这些规则。

个人数据如何使用 Git，由用户明确选择：

- 保持默认忽略，只在本地保存数据，并用完整私人备份保护整个项目。
- 确认远端是自己的私有仓库后，仅在自己的副本调整个人数据的忽略规则，明确选择需要跟踪的记录、
  设置和个人指南。核对实际暂存与已跟踪文件，再提交和同步；不要把此项个人选择回写公共模板。

引擎不自动替用户选择跟踪范围。`git push` 只上传已提交的历史，不会备份被忽略且未跟踪的文件，也不会保存未提交的更改。
`.hl` 中的密钥与完整操作状态仍由私人完整备份保存，不通过取消全部忽略规则来代替备份。

备份和换机时复制整个项目，包括隐藏的 `.hl`、个人规则和本地数据；`.venv` 是可重建的机器环境，
可以不搬。新电脑在同一份项目中重新 bootstrap，再 check 和 doctor。
`.hl` 是账本的一部分，不能与 `.venv` 一起清理。具体操作见[迁移与备份](migration.md)。

## 升级与公开分发是两件事

自己的项目升级时，只更新程序允许清单内的源码、入口、文档、依赖声明和公开运行资源。
保留 `hl.toml`、`log/`、`plan.yaml`、`defaults.yaml`、`foods/`、`.hl/` 和个人指南；
根 `AGENTS.md` 等实际规则需比较后合并。公开新版没有的私有文件不能因此被删除。
完整第三方 `raw`、`compiled` 数据继续私有保留；程序升级也不自动迁移账本格式。

维护者生成公共源码快照时，按 `pyproject.toml` 的明确允许清单选择文件；wheel 只带运行代码和资源。
测试、过程材料、个人账本、凭据和受限第三方完整数据即使还在维护者目录里，也不能进入公开产物。
发布前重新构建并逐项检查实际 wheel、源码包和源码快照，不能只看 `.gitignore` 或沿用旧包。

`.gitignore` 不能抹掉已跟踪文件或 Git 历史。含私有开发材料的旧仓库应继续私有；
公共项目从审阅后的干净源码快照建立独立历史，不直接把旧开发仓库改为公开。
公开问题、附件、自动化日志和发布包也遵守同样边界。

程序与自有规则采用 [MIT 许可证](../LICENSE)，不改变个人项目的访问权限；第三方食品数据遵循各自来源条款，
范围见[项目数据说明](../data/foods/README.md)。构建清单配置参考
[Hatch 文件选择说明](https://hatch.pypa.io/latest/config/build/#explicit-selection)。
不公开测试是本项目的分发选择，不是 Python 或 GitHub 的统一规定。
